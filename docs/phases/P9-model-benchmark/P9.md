# Phase 9 — Model benchmark: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan slice by slice, task by task. Steps use checkbox (`- [ ]`) syntax for tracking. Each slice file `S-<nn>-*.md` in this folder is one unit of work with its own tasks; this file holds what every slice shares.

**Goal:** A team can measure which model does each agent's work best on its own project, keep the numbers in the repository, and set a model per role from them (REQ-6.1, D-108). A run is started by a person or an opt-in CI job, is refused without a spending cap, and never sets a model itself (D-112, D-125). A newly released model can be run against the current one on the same tasks (D-117).

**Architecture:** Two new CLI commands, `slicekit models` and `slicekit bench`, and one new folder of benchmark modules under src, with one module per part of D-110: the task picker, the runner, the scorer, the report and the new-model check. Two adapters with stand-ins for tests: Claude Code run headless (C-4, `SLICEKIT_CLAUDE`) and Anthropic's models API (C-7, `SLICEKIT_MODELS_FIXTURE`). The model of each role is written by the renderer, so `slicekit update` keeps it (D-115).

- **Models per role** (S-64): `models` in `.slicekit/config.json`; the renderer writes `model:` into each agent file and each per-command file; `slicekit models apply` renders and lists the changes.
- **Task picker** (S-65): `slicekit bench pick` and `--confirm`; tasks from merged slices with frozen tests, the planted defects of D-123, the fixer replay of D-127, the designer screens of D-129, and the built-in pack.
- **Runner** (S-66): `slicekit bench run`; one `claude -p` per trial in a folder with no git, the trial count of D-124, the estimate and cap of D-112 and D-125, the run file.
- **Scorer** (S-67): the per-agent scores of REQ-6.4, written into each trial of the run file.
- **Report** (S-68): `slicekit bench report`; `<docsRoot>/benchmark/report.md` from the run files, Wilson intervals, pass^k and the suggestion of D-126.
- **New-model check** (S-69): `slicekit bench check` against the models API, and the opt-in scheduled workflow that opens a pull request.

**Tech Stack:** As Phases 1 to 8: Node ≥ 22, ES modules, `node:test`, `node:child_process` for git, `gh` and `claude`, `fetch` for the models API, no dependencies (D-04).

**Spec:** `docs/spec/06-model-benchmark.md` (REQ-6.1 to REQ-6.10), contracts C-4 to C-8, `docs/spec/05-kit-quality-and-release.md` (REQ-5.7, REQ-5.8). Decisions: `docs/decisions.md` (D-108 to D-130 bind this phase). No slice changes a spec file.

## What already exists

- Each agent template in `templates/claude-code/agents/` carries `model: inherit` as fixed text. A front-matter file is managed whole (`src/render/managed.js`), so `slicekit update` rewrites it; a value set by hand is lost on the next update. `varsFor` in `src/render/entry.js` gives the templates `version`, `name`, `docsRoot` and `cli` only.
- Each procedure has a per-command file, `templates/claude-code/commands/slicekit-<command>.md`, with a `description` in its front matter, and `/slicekit <command>` reaches the same procedure through `slicekit.md`.
- `validateConfig` in `src/config.js` refuses an unknown top-level key, so `models` and `bench` need entries there.
- A slice's state file records `redCommit` and its frozen tests by name (`src/state/index.js`, `src/testnames.js`); `findTest` finds a named test's body. Verdict files parse with `parseVerdict` in `src/verdict.js`, and the state file's history holds each round's verdict.
- `renderWorkflow` in `src/workflow.js` writes `.github/workflows/slicekit.yml` from `templates/workflow/slicekit.yml`; there is no second workflow.
- `examples/backend`, `examples/data` and `examples/fullstack` are projects with no git history of their own.

## Global Constraints

Every constraint of `docs/phases/P1-spine/P1.md`, `docs/phases/P2-loop/P2.md` and `docs/phases/P6-polish/P6.md` holds, except the commit trailer. In addition:

- **No model call in a test.** Tests set `SLICEKIT_CLAUDE` to a stand-in script that prints recorded JSON, and `SLICEKIT_MODELS_FIXTURE` to a listing file. No test reaches Anthropic, a git host or the network.
- **Nothing is spent without a cap.** Every path that starts a trial goes through the one cap check of S-66; a test pins that no trial starts with no cap set.
- **A trial cannot see the answer.** A trial folder holds no `.git`, no remote and no file of the hidden reference answer; a test lists the folder.
- **No key on disk.** No file the kit writes holds the value of `ANTHROPIC_API_KEY`; a test sets a known value and searches every file the run wrote.
- **The benchmark never sets a model.** Only `slicekit models apply`, run by a person, writes a `model:` field (D-109, D-112).
- **Guide pages follow the code, in the slice that adds the command.** Each slice that adds or changes a command writes its page and regenerates `docs/guide/slicekit-guide.html`; the Order runs one such slice per step.
- **Subcommand output.** As P2: the first stdout line is the value; findings one per line as `<file>:<line> <message>`; exit 0 success, 1 refused or findings, 2 usage or unknown ID.
- Commits on the kit's own repo end with ONE final block of two lines, `Slice: P9/S-<nn>` immediately followed by the `Co-Authored-By` line of the session that made the commit.

## Review Focus

1. **A trial that reads the answer.** The trial folder holds no `.git` and no file of the reference answer. Pinned by `bench-run.test.js » a trial runs in a folder with no git entry and records the full model id and the Claude Code version` (S-66).
2. **Money spent without consent.** No trial starts with no cap set, or before the person goes on after the estimate. Pinned by `bench-run.test.js » with no cap set a run is refused naming the setting` (S-66).
3. **A key written to disk.** Pinned by `bench-run.test.js » no file the run wrote holds the API key` (S-66).
4. **A suggestion on noise.** With too few tasks the report names no model. Pinned by `bench-report.test.js » with one task the report names no suggested model and says there were too few tasks to tell` (S-68).
5. **A model switched by a job.** The scheduled workflow opens a pull request and changes no `models` entry. Pinned by `bench-check.test.js » the scheduled workflow opens a pull request and changes no models entry` (S-69).

## Order

**Order:** A; B; C; D; E; F

The six slices run one after another. Each adds or changes a command and its guide page, so each rewrites `docs/guide/slicekit-guide.html`, and S-65 to S-69 all change `src/cli/bench.js`. Each also needs the one before it: the runner runs the picker's tasks, the scorer scores the runner's trials, the report reads the scored run files, and the check runs the runner and regenerates the report.
