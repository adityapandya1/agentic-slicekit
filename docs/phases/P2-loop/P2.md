# Phase 2 — Loop: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan slice by slice, task by task. Steps use checkbox (`- [ ]`) syntax for tracking. Each slice file `S-<nn>-*.md` in this folder is one unit of work with its own tasks; this file holds what every slice shares.

**Goal:** A team can go from a requirement document to merged slices: `/slicekit intake`, `specify`, `gaps`, `plan`, `build` and `review` each run end to end, with every deterministic step done by a tested `slicekit` subcommand.

**Architecture:** A slash command is a pointer. The rendered `.claude/commands/slicekit-<name>.md` holds one line that runs `slicekit instructions --command <name> $ARGUMENTS`; the procedure it prints lives in `templates/instructions/commands/<name>.md`, and each agent's brief lives in `templates/instructions/agents/<role>.md`, served by `slicekit instructions <role> [P<n>/S-<nn>]`. This keeps the rules in one home (REQ-2.12), lets a kit upgrade change a procedure without a re-render, and gives each parallel slice its own file. A procedure is instructions to Claude Code: ask the human, spawn an agent, read its report, call the CLI. Everything that must hold every time (snapshots, decision rows, branches, worktrees, commits, pushes, pull requests, issues, state moves, verdict recording, the two-round cap) is a CLI subcommand with tests. Group A (S-09) builds the plumbing every later slice calls (`instructions`, `decide`, `stage`, `branch`, `pr`, the C-1 write operations, the pull request body, the Order parser); groups B and C then touch disjoint files.

**Tech Stack:** As Phase 1: Node ≥ 22, ES modules, `node:test`, `node:child_process` for git and `gh`, no dependencies. `fetch` (global in Node 22) for URL intake.

**Spec:** `docs/spec/02-commands-agents-loop.md` (REQ-2.1 to REQ-2.8, REQ-2.10 to REQ-2.12), with REQ-1.2 to REQ-1.9 and REQ-1.11 of `docs/spec/01-layout-and-state.md`; contracts C-1 and C-2 in `docs/spec/contracts/`. REQ-2.9, REQ-2.13 and REQ-2.14 are Phase 4. Decisions: `docs/decisions.md` (D-06, D-07, D-09, D-10, D-17, D-18, D-19, D-22, D-28, D-35, D-40, D-41, D-42 and D-43 bind this phase).

## Global Constraints

Every constraint of `docs/phases/P1-spine/P1.md` holds, except the commit trailer. In addition:

- **Commands own git (D-19, REQ-2.1).** A procedure (`templates/instructions/commands/<name>.md`) contains no `git` or `gh` command; every git and git-host operation it needs is a `slicekit` subcommand. An agent brief names a git command that writes or moves history only in the sentence that forbids it; read-only `git diff`, `git log`, `git show` and `git status` are allowed, as pre-bash allows them. The brief lint in `test/helpers/brief-lint.js` checks both.
- **Subcommand output.** On success the first stdout line is the value a procedure needs (an ID, a path, `#<n> <url>`, `next: <step>`); findings go one per line as `<file>:<line> <message>`. Exit 0 success, 1 refused or findings, 2 usage or unknown ID. Each command object with subcommands is `{run, usage, subcommands: string[]}`, so the brief lint can check `{{cli}} <command> <sub>`.
- **Placeholders.** Templates under `templates/instructions/` use `{{cli}}` (the configured hook command, D-30) and, in procedures, `{{args}}`; nothing else is substituted.
- **Hosts through adapters.** The git host only through `getHost` (C-1), the tracker only through `getTracker` (C-2). Tests set `SLICEKIT_GITHOST_FIXTURE` and `SLICEKIT_TRACKER_FIXTURE` to a temp copy of a fixture directory; no test reaches the network (the URL intake test serves from `127.0.0.1`).
- **Git in tests.** Tests that commit or push use `makeRepo` and a new `makeRemote(root) → {remote, cleanup}` (a bare repository set as `origin`), which S-09 adds to `test/helpers/tmp-repo.js`.
- **Slice commits.** Every commit a `build` subcommand makes carries `Slice: <id>` in its message itself. State, `BUILD.md` and verdict files go in bookkeeping-only commits (`chore(slicekit): <id> <what>`) touching nothing else, so a verdict survives them (D-35).
- **State.** Moves go through `recordState` (S-14), which calls `setState`, rewrites `BUILD.md` and commits both. Nothing else writes `.slicekit/state/`.
- **Worktrees.** `build start` puts a slice's worktree at `<root>/.worktrees/P<n>-S-<nn>`, `review start` at `<root>/.worktrees/review-P<n>-S-<nn>`. Every later `build` subcommand finds the worktree from the slice ID (`--worktree <path>` when two hold it), so a procedure runs from the main checkout. `build start` pushes the new branch at once, so another clone's `build next` skips the slice; the `.worktrees` directory is git-ignored.
- **Verdicts.** A reviewer writes its verdict to `<session root>/.slicekit/reviews/P<n>-S-<nn>[i]-r<k>.md`, where subagent-stop looks for it; `build verdict` moves it into the slice worktree and commits it. `k` counts every verdict of the slice; the letter `i` marks an independent one.
- **Order.** A phase file may carry a line `**Order:** <step>; <step>; …`, each step a comma list of groups that run in parallel; this file's own line is the example. Without the line, each group is its own step in name order. `build next` and `build parallel` read it; `check` validates it; S-13 gives it a home in REQ-1.5 and D-38.
- Commits on the kit's own repo end with ONE final block of two lines, `Slice: P2/S-<nn>` immediately followed by `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Decision text holding `|`, a backtick or a line break.** A `|` must not split the table row; a line break is refused, not written. Pinned by `decisions.test.js » a pipe in the answer is escaped and a newline is refused` (S-09).
2. **A pull request body a human edited between rounds.** Updating "Reviewer blocked" or "Should-haves declined" keeps every other line the human wrote. Pinned by `prbody.test.js » setSection keeps text outside the section` (S-09).
3. **A step re-run after a partial failure.** The push succeeded and opening the pull request failed: the re-run opens it once and records `draft-pr` once. Pinned by `commands/build.test.js » a re-run after a failed open opens the pull request once` (S-14).
4. **Test paths given absolute or with backslashes.** They are stored relative and POSIX, so the frozen-test guard matches them. Pinned by `commands/build.test.js » absolute and backslash test paths are stored relative` (S-14).
5. **A docs root of `.` with worktrees under the root.** `check` in the main checkout must not read the `.worktrees` directory (duplicate slice IDs, doubled style counts). Pinned by `commands/build.test.js » a docs root of . does not read the worktrees` (S-14).

## Order

**Order:** A; B, C; D; E; F; G; H; I

Groups: A, then B and C in parallel, then D, then E, then F, then G, then H, then I. S-15 (D) finishes the build command S-14 (C) starts, and S-16 (E) adds review and `--parallel` to it. The preview slice S-25 (F) comes last: it writes the README walkthrough a test runs verbatim, after which the repository goes public as a preview (D-28). S-26 (G) then makes 0.1.1 the first version on npm, as a preview (D-40, D-41). S-27 (H) makes the git hooks cheaper, which is most of the Windows test time (D-42). S-28 (H, beside S-27) ships 0.1.2 with what a first npm install needs: node_modules ignored, npm arguments quoted on Windows, both placeholders deprecated. S-29 (I) removes the dead ends S-26 to S-28 hit in the build loop, so no slice needs a hand commit (D-43).
