# Phase 8 — Lighter loop: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan slice by slice, task by task. Steps use checkbox (`- [ ]`) syntax for tracking. Each slice file `S-<nn>-*.md` in this folder is one unit of work with its own tasks; this file holds what every slice shares.

**Goal:** A slice costs fewer steps, commits and review rounds than in Phase 6. A merge of the default branch no longer conflicts on `BUILD.md` or resets a review whose files it did not touch (D-100); review rounds have a budget that ends in a person's choice (D-101); freezing holds a test by its name, and every slice-file change has a command (D-102); a slice that changes no code takes a quick lane (D-103); and one command prints and runs the next step from files alone, so `/loop` can drive the build loop across restarts (D-104).

**Architecture:** One new CLI command, `slicekit next`, and one new procedure, `next`; one new check rule, `lane`; one new front-matter field, `lane`; one merge driver that init registers. Every other change lands in the file that holds the behaviour.

- **BUILD.md** (S-58): `commitState` in `src/build/record.js` commits the slice's state file alone. The queue rule reports nothing on a slice branch. `headCovers` in `src/state/covers.js`, which `state set ready`, `build pr` and the ready label read through it, also counts a merge of the default branch that leaves every file the pull request changes, bookkeeping aside, as it was at the verdict's head. Init writes `BUILD.md merge=slicekit-build` to `.gitattributes` and sets `merge.slicekit-build.driver` in the clone's git config to a `slicekit status` mode that writes the rendered file over git's result.
- **Review budget** (S-59): `review start` refuses a second independent round unless the first left a blocker, and a third unless a decision row names the slice and allows it; the refusal names the open findings and the three choices of REQ-2.8. The reviewer's brief forbids a style finding and says `APPROVE` with an empty findings table is the answer when nothing is found. The review procedure says a reviewer subagent started by `review start` from the main checkout, with no build context, counts as independent (D-104).
- **Freezing by name** (S-60): `build red` records each evaluation test as `{file, name}`; the pre-edit hook, the `frozen` rule and `build commit` compare the body of each named test, not the file; `build amend --test <name>` unfreezes one test, and `build amend` with no test records any slice-file change with its reason; the pre-edit hook lets through a new document that the slice file's Expected changes names.
- **Quick lane** (S-61): `parseSliceFile` reads `lane: quick`; the `lane` rule refuses one whose expected changes or branch changes reach `src/`, `bin/` or `templates/`; `LOOP_ROUNDS` becomes a function of the lane; the plan and build procedures describe the one combined plan step and the one in-loop round. S-61 also carries the guide pages of S-59 and S-60 (see Order).
- **Next step** (S-62): `src/next.js` reads `.slicekit/state/`, the slice files, the verdict files and `decisions.md`, and returns one step and its command, or a stop for a person. `slicekit next` prints it; `/slicekit next` runs it and stops. <!-- slicekit:pending P8/S-62 -->
- **Open issues** (S-63): the guard, release-version, staged-run and guide-script issues listed below, each with a test.

**Tech Stack:** As Phases 1 to 7: Node ≥ 22, ES modules, `node:test`, `node:child_process` for git and `gh`, no dependencies (D-04).

**Spec:** `docs/spec/01-layout-and-state.md` (REQ-1.1, REQ-1.5, REQ-1.6, REQ-1.8), `docs/spec/02-commands-agents-loop.md` (REQ-2.5, REQ-2.6, REQ-2.8, REQ-2.11, REQ-2.12, REQ-2.16), `docs/spec/03-hooks-gates-ci.md` (REQ-3.2, REQ-3.3, REQ-3.7, REQ-3.11, REQ-3.15), `docs/spec/05-kit-quality-and-release.md` (REQ-5.6, REQ-5.7, REQ-5.8). Decisions: `docs/decisions.md` (D-100 to D-104 bind this phase; D-35, D-10, D-18 and D-97 are refined or kept). No slice changes a spec file.

## What already exists

- `commitState` in `src/build/record.js` renders `BUILD.md` and commits it with the slice's state file on every state move, so every slice branch changes `BUILD.md`. The queue rule (`src/check/rules/queue.js`) compares `BUILD.md` with the state files on every branch.
- `headCovers` in `src/state/covers.js` (D-35) holds a verdict on a later head only when every file changed between the two heads is bookkeeping: the state folder, `.slicekit/reviews/`, the journal folder and `BUILD.md`. A merge of the default branch brings other files, so it resets the verdict.
- Init writes `.gitattributes` with `.githooks/* text eol=lf` and `<docsRoot>/intake/** -text` (`attributeRules` in `src/init.js`); no file of `src/` writes a `merge=` attribute or a merge driver.
- `LOOP_ROUNDS = 2` in `src/build/verdict.js` bounds the in-loop rounds. `startReview` in `src/build/review.js` numbers an independent round as the verdict count plus one and refuses none by count.
- The state file holds `frozenTests` and `unfrozen` as lists of file paths (`src/state/index.js`). The pre-edit hook denies any edit to a listed file (`judge` in `src/hooks/pre-edit.js`); the `frozen` rule finds a change by `git diff --name-only` over the listed files (`src/check/rules/frozen.js`). `build amend --test <file>` on a file already unfrozen refuses with `<file> is already unfrozen` (`src/build/commit.js`), which is issue #187.
- The pre-edit hook denies a new file under the docs root while a slice is `tests-red` or `building`, except the runbook and a file in the slice's own phase folder.
- `slicekit build next` prints the ID of the next runnable slice or `no slice is ready to build`; no command prints the next step of the loop for a slice already started.
- `parseSliceFile` in `src/slicefile.js` reads the scalars `slice`, `name`, `repo`, `group` and `runbook`; it has no `lane`. Check rules are loaded from the files under `src/check/rules/`.
- `docs/guide/slicekit-guide.html` must equal what `scripts/guide-html.js` writes from the pages (`test/guide-page.test.js`), so a slice that changes a guide page also writes the web page.

## Global Constraints

Every constraint of `docs/phases/P1-spine/P1.md`, `docs/phases/P2-loop/P2.md` and `docs/phases/P6-polish/P6.md` holds, except the commit trailer. In addition:

- **A guard that cannot judge refuses.** S-60 narrows what the pre-edit hook freezes, from a file to a named test; a test whose name the hook cannot find in the file after the edit, or whose file it cannot parse, is denied. Each task of S-60 and S-63 that changes a file under `src/hooks/` runs the whole of `test/hooks/` before it commits, and a test that passed before the slice passes unchanged unless the slice file names it.
- **The default branch still holds the truth.** After S-58, `BUILD.md` on the default branch equals what `slicekit status --write` renders after every sync; a slice branch's `BUILD.md` is no longer judged. The sync job of REQ-3.11 is unchanged.
- **The independent review stays required.** No slice of this phase lets a slice reach `ready` without an independent verdict when `review.independent` is `required`, the quick lane included.
- **`slicekit next` writes nothing.** A test runs it on a fixture and compares every file's bytes before and after.
- **No host or tracker in a test.** Tests set `SLICEKIT_GITHOST_FIXTURE`; no test reaches the network, publishes or pushes a tag.
- **Guide pages follow the code, in the slice that owns the web page.** A slice that changes a guide page regenerates `docs/guide/slicekit-guide.html` in the same pull request. Within one Order step only one slice does so (see Order).
- **Subcommand output.** As P2: the first stdout line is the value; findings one per line as `<file>:<line> <message>`; exit 0 success, 1 refused or findings, 2 usage or unknown ID.
- Commits on the kit's own repo end with ONE final block of two lines, `Slice: P8/S-<nn>` immediately followed by the `Co-Authored-By` line of the session that made the commit.

## Review Focus

1. **A conflict on BUILD.md.** A merge of the default branch into a slice branch whose state moved completes with no conflict, and `BUILD.md` afterwards equals what `status --write` renders. Pinned by `build-merge-driver.test.js » a local merge regenerates BUILD.md through the merge driver with no conflict` (S-58).
2. **A merge that hides a change.** A merge of the default branch that changes a file the pull request changes resets the verdict as before. Pinned by `covers.test.js » a merge that changes a file the pull request changes does not cover the verdict` (S-58).
3. **A frozen test changed under another name.** Renaming a frozen test or moving its body leaves the named test missing, which is a finding and a denial, never an allow. Pinned by `hooks/pre-edit.test.js » an edit that removes or renames a frozen test is denied` (S-60).
4. **A quick slice that reaches code.** A `lane: quick` slice whose branch changes `src/init.js` is a finding. Pinned by `check/lane.test.js » a quick slice whose branch changes a file under src is a finding naming the path` (S-61).
5. **A next step that acts for a person.** At `ready`, at an Open row and at a budget stop `slicekit next` prints the human's command and exits 0 without running it. Pinned by `next.test.js » at ready next names the merge for a person and changes no file` (S-62).
