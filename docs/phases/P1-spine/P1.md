# Phase 1 — Spine: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan slice by slice, task by task. Steps use checkbox (`- [ ]`) syntax for tracking. Each slice file `S-0n-*.md` in this folder is one unit of work with its own tasks; this file holds what every slice shares.

**Goal:** A team can run `npx slicekit init` in any repository and get the layout, the Claude Code files, the hooks, the gate (`slicekit check`), the state machine and the CI workflow, and the kit can enforce its own rules on itself.

**Architecture:** One zero-dependency Node CLI (`bin/slicekit.js` → `src/cli/index.js`) with pure modules under `src/` that take a repository root and return data; the CLI, the hooks and CI are thin callers. Every hook is `slicekit hook <name>` reading JSON on stdin and writing JSON on stdout. Every rule of the gate is one file under `src/check/rules/`. State is one JSON file per slice, written only through `src/state/`.

**Tech Stack:** Node ≥ 22, ES modules, `node:test` + `node:assert/strict`, `node:child_process` for git and the team's commands, `node:crypto` for hashes. No dependencies.

**Spec:** `docs/spec/00-overview.md` through `05-kit-quality-and-release.md`, contracts in `docs/spec/contracts/`. Decisions: `docs/decisions.md`. Milestone: the kit installs and checks itself (D-16).

## Global Constraints

- `package.json` has `"type": "module"`, `"engines": {"node": ">=22"}`, no `dependencies` (REQ-5.3, D-29).
- Tests are `node --test "test/**/*.test.js"`; helpers and fixtures under `test/` are never test files. They pass on Windows, macOS and Linux (REQ-5.2). Paths are built with `node:path`; files are read and written as UTF-8 with LF; markdown parsing tolerates CRLF.
- Exit codes: 0 success, 1 findings or refused transition, 2 usage error.
- Adapter files rendered into `.claude/` carry `slicekit-managed: v<version>` in their front matter and are managed whole. Files without front matter, and every file rendered into `.githooks/` and `.github/workflows/`, use comment markers (`<!-- slicekit:managed:start v<version> -->` … `<!-- slicekit:managed:end -->`, or `# slicekit:managed:start v<version>` … `# slicekit:managed:end` for `#`-comment files) and are managed block-wise (REQ-3.12). `.slicekit/config.json` and the seeded docs are the team's and carry no markers. <!-- slicekit:example -->
- Hook output follows Claude Code's protocol: PreToolUse deny is `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":"…"}}`; SessionStart context is `{"hookSpecificOutput":{"hookEventName":"SessionStart","additionalContext":"…"}}`; Stop and SubagentStop block with `{"decision":"block","reason":"…"}`; allow is an empty object and exit 0.
- Fail-open hooks (SessionStart, SubagentStart, PreCompact, SessionEnd) exit 0 on every error and print why to stderr. Fail-closed hooks (PreToolUse, SubagentStop, Stop) deny or block when their own logic errors, with the error in the reason.
- IDs: `REQ-<s>.<n>`, `D-<n>`, `G-<n>`, `C-<n>`, `P<n>`, `S-<nn>`; slice address `P<n>/S-<nn>`; branch `slice/P<n>-S-<nn>-<descr>`; trailer `Slice: P<n>/S-<nn>` (REQ-1.9).
- Writing rules of `docs/spec/00-overview.md` apply to every template, message and doc the kit emits; the seed filler list is in `templates/style.json`.
- Commits on the kit's own repo end with ONE final block of two lines, `Slice: P1/S-0n` immediately followed by `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`, with no blank line between them (git reads trailers from the last paragraph only).

## Review Focus

1. **A repository with no commits yet.** `init` and `check` must work before the first commit; `git log` fails there. Pinned by `test/init.test.js » init on a repo with no commits` (S-01) and `test/check/trailer.test.js » no commits is not a finding` (S-06).
2. **CRLF and Windows paths in every parser.** Markdown from Windows editors, hook stdin with `\r\n`, backslash paths in `file_path`. Pinned by `test/markdown.test.js » parses CRLF` (S-01) and `test/hooks/pre-edit.test.js » backslash path matches frozen file` (S-06).
3. **An empty command string is "not declared", not "missing".** `commands.e2e: ""` must not fail the commands rule. Pinned by `test/check/commands.test.js » empty command is skipped` (S-05).
4. **Two slices writing state at once.** Atomic write (temp file + rename) and per-slice files; a half-written file must never be read. Pinned by `test/state.test.js » write is atomic` (S-03).
5. **Hook stdin that is empty, truncated or not JSON.** Fail-open hooks exit 0 silently; fail-closed hooks deny with "could not read hook input". Pinned by `test/hooks/protocol.test.js » each hook with empty stdin` (S-06, S-07).
