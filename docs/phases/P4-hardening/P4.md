# Phase 4 — Hardening: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan slice by slice, task by task. Steps use checkbox (`- [ ]`) syntax for tracking. Each slice file `S-<nn>-*.md` in this folder is one unit of work with its own tasks; this file holds what every slice shares.

**Goal:** Close the gaps the 2026-11-02 architect review lists (`docs/intake/2026-11-02-architect-review.md`, lines 144 to 151) that D-64 to D-82 keep in scope, before the Ops phase, now Phase 5, starts (D-64). A team that adopts the kit gets controls that hold on the git host and in CI, not only on the developer's machine: the host's branch rules verified, frozen tests checked in CI, guards that refuse what they cannot parse, a path deny-list for agents, a journal tied to signed commits, a sync job that opens a pull request instead of pushing, a Java-ready workflow on the team's runners, and Jira Cloud as a tracker.

**Architecture:** Every control is a deterministic `slicekit` subcommand, a check rule or a line of the generated workflow. The guards on the developer's machine stay, and are named for what they are: checks that can be bypassed (REQ-2.1). The controls are the host's rules (REQ-3.14), CI's check (REQ-3.15, REQ-3.8) and a human merge.

- **Guards** (S-37, S-39): `pre-bash` gains a refusal for every command it cannot judge from its text (a variable or command substitution in a git command, `eval`, a shell's `-c`, an interpreter's inline code naming `git` or `gh`) and for a Bash write to a frozen test. `pre-edit` and `pre-bash` gain the `agents.denyPaths` list, which the renderer also writes into Claude Code's permission deny rules.
- **CI rules** (S-38, S-40, S-42): three check rules read git objects and the host, never the working tree: `frozen` (REQ-3.15), `host-rules` (REQ-3.14) and the journal rule's signature check (REQ-3.8). Each is stubbed in tests by `SLICEKIT_GITHOST_FIXTURE`.
- **The sync job** (S-41): `slicekit sync open` pushes the state change to `sync/<short sha>`, opens a `[sync]` pull request through C-1, then starts the workflow on that branch through C-1 `dispatchWorkflow` (D-78, D-80). It never pushes to the default branch.
- **The workflow** (S-43): `ci.runsOn` and a JDK step when the repository is a Maven or Gradle project (D-67, D-69).
- **Trackers and agent tools** (S-44): `src/adapters/tracker/jira.js` behind `getTracker`; `docs/adapters.md` gains the exit path for a second agent tool (D-74, D-75).

**Tech Stack:** As Phases 1 to 3: Node ≥ 22, ES modules, `node:test`, `node:child_process` for git and `gh`, no dependencies (D-04). Jira is reached with the global `fetch`.

**Spec:** `docs/spec/02-commands-agents-loop.md` (REQ-2.1, REQ-2.6), `docs/spec/03-hooks-gates-ci.md` (REQ-3.2, REQ-3.3, REQ-3.7, REQ-3.8, REQ-3.11, REQ-3.13 to REQ-3.15), `docs/spec/01-layout-and-state.md` (REQ-1.1, REQ-1.8), `docs/spec/05-kit-quality-and-release.md` (REQ-5.8), contracts C-1 to C-3. Decisions: D-64 to D-82 bind this phase; D-10, D-19, D-32, D-36 and D-43 still hold.

## What already exists

- `pre-bash` denies literal commits and pushes on a protected branch, force pushes, and `git commit`, `git push` and `gh pr` from a subagent; its header lists the forms it does not parse (`src/hooks/pre-bash.js:13-25`).
- `pre-edit` denies an edit to a frozen test through Edit and Write; `build commit` diffs frozen tests against the red commit (`src/build/commit.js:48-64`). No check rule judges frozen tests in CI.
- The journal rule verifies the chain and the byte prefix against the default branch; nothing checks commit signatures.
- The sync job in `src/workflow.js` commits state and `BUILD.md` straight to the default branch with `ALLOW_PROTECTED_COMMIT=1`.
- Every job of the generated workflow runs on `ubuntu-latest` (the kit's own test matrix on three systems) and sets up Node only.
- `getTracker` picks an implementation from `cfg.tracker.kind`; only `github-issues` exists.
- Check rules are loaded from every file in `src/check/rules/`, so a new rule adds a file and touches no registry.

## Global Constraints

Every constraint of `docs/phases/P1-spine/P1.md` and `docs/phases/P2-loop/P2.md` holds, except the commit trailer. In addition:

- **Commands own git (D-19).** The new rules read git; only CI's generated YAML pushes the sync branch.
- **No host setting changes but one.** Only `slicekit init --protect`, run by a human, calls `applyBranchRules`. No agent, hook, rule or CI job changes a host rule (D-77).
- **One door to the host (C-1).** New host calls go through `getHost`; tests set `SLICEKIT_GITHOST_FIXTURE` and `SLICEKIT_TRACKER_FIXTURE`; no test reaches the network.
- **No secrets in files.** Jira's email and token are read from the environment only and never printed (D-74).
- **Rendered files.** A template change reaches the kit's own `.claude/` through `build render` (D-43), never by hand; a workflow change reaches `.github/workflows/slicekit.yml` through `slicekit workflow --write`.
- Commits on the kit's own repo end with ONE final block of two lines, `Slice: P4/S-<nn>` immediately followed by `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
