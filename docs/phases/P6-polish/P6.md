# Phase 6 — Polish: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan slice by slice, task by task. Steps use checkbox (`- [ ]`) syntax for tracking. Each slice file `S-<nn>-*.md` in this folder is one unit of work with its own tasks; this file holds what every slice shares.

**Goal:** Every issue open on the repository when this plan was written is closed by a change with a test, or by a runbook line where the kit's code cannot answer it; a phase gets its minor version once (D-96); and the user guide has one source, the pages under `docs/guide/`, from which its web page is generated (D-97).

**Architecture:** No new command and no new config key. Each fix lands in the file that holds the behaviour, and each has a test that failed before it.

- **Versions** (S-51): `releaseFor` in `src/release-version.js` already takes the changelog as the record of which slices have a version (D-92). It takes it as the record of which phases have their minor version too: a phase whose line a `CHANGELOG.md` section on the default branch holds has had it, and a slice merged into that phase later is a patch version naming that slice alone (D-96). The `sync-release` rule recomputes with the same function, so the sync job and CI cannot differ.
- **The build loop** (S-51): `build commit` reads the slice's state file from disk, so it refuses one that git cannot see or that differs from the commit; its test run on the staged content can read the files git does not track and can run git. The `frozen` rule reads the state file's history, so a tip that removed the file is still judged.
- **Guards** (S-52): `pre-bash` and `pre-edit` read more of what a shell or a link can spell: a host-rule write through GraphQL or a full URL, more ways to write a frozen test, a `cd` whose target is a glob or sits inside a backtick substitution, and a listed path named through a link. `validateConfig` compiles each `agents.denyPaths` pattern with the guards' own code, so a pattern the guards cannot compile is refused where the config is read.
- **Jira** (S-53): `find` sends a search value Jira's text search can parse and follows `nextPageToken`; the promise path of `build decline` gets tests.
- **The guide** (S-54): a script under `scripts/`, with no dependency, writes `docs/guide/slicekit-guide.html` from the index `docs/guide/README.md` and the pages it links. A test runs the same function and compares bytes. The page holds no version and no date, so a sync that sets a version does not make it stale. The PDF copies are rendered from the web page outside the repository and leave it (D-97).

**Tech Stack:** As Phases 1 to 5: Node ≥ 22, ES modules, `node:test`, `node:child_process` for git and `gh`, no dependencies (D-04). The guide script uses `node:fs` and `node:path` only.

**Spec:** `docs/spec/02-commands-agents-loop.md` (REQ-2.6, REQ-2.9), `docs/spec/03-hooks-gates-ci.md` (REQ-3.2, REQ-3.3, REQ-3.8, REQ-3.11, REQ-3.13, REQ-3.14, REQ-3.15), `docs/spec/01-layout-and-state.md` (REQ-1.1), `docs/spec/05-kit-quality-and-release.md` (REQ-5.5, REQ-5.6, REQ-5.8), `docs/spec/contracts/C-2-tracker.md`. Decisions: `docs/decisions.md` (D-10, D-43, D-61, D-72, D-74, D-80, D-83, D-88, D-90, D-92 and D-94 bind this phase). No slice changes a spec file.

## What already exists

- `build commit` refuses a frozen test marked `skip-worktree` or `assume-unchanged` (`frozenProblem` in `src/build/commit.js`); it makes no such test of the slice's own state file, which it reads from disk (issue #71). With paths staged it runs the tests in a temporary directory that holds the index and a link to `node_modules`, and nothing else (issue #107).

- `slicekit branch release` answers a numbered slug whose branch holds its own commits by appending to the slug given (issue #170), and after dropping a migrated config it can leave the file staged (issue #171).
- A probe of `handle` in `src/hooks/pre-bash.js` on 2026-11-15 allowed every command the guard issues name, and `cat src/[z-a].js` threw the regular-expression error of issue #119; `validateConfig` returned no error for the pattern `[z-a]` (issue #120).

## Global Constraints

Every constraint of `docs/phases/P1-spine/P1.md`, `docs/phases/P2-loop/P2.md` and `docs/phases/P5-ops/P5.md` holds, except the commit trailer. In addition:

- **A test first, for every issue.** Each issue's fix has a test that fails on the default branch as it is before the slice. A fix with no failing test first is not done.
- **A guard that cannot judge refuses.** A change to `pre-bash` or `pre-edit` never turns a deny into an allow. Each task of S-52 runs the whole of the hook tests under `test/hooks/` before it commits, and a test that passed before the slice passes unchanged.
- **No host or tracker in a test.** Tests set `SLICEKIT_GITHOST_FIXTURE`; the Jira tests pass a `fetch` in or replace the global one for the test and restore it. No test reaches the network, publishes or pushes a tag.
- **The web page has one writer.** `docs/guide/slicekit-guide.html` is written only by the guide script. Its bytes depend on the files under `docs/guide/` and on the script, and on nothing else: no version, date, user name or absolute path. A test compares after reading CRLF as LF.
- **Guide pages follow the code.** A slice that changes what a command or a rule does changes its page under `docs/guide/` in the same slice. The web page is regenerated in S-54 and not before, since its test arrives there.
- **Subcommand output.** As P2: the first stdout line is the value; findings one per line as `<file>:<line> <message>`; exit 0 success, 1 refused or findings, 2 usage or unknown ID.
- Commits on the kit's own repo end with ONE final block of two lines, `Slice: P6/S-<nn>` immediately followed by the `Co-Authored-By` line of the session that made the commit.

## Review Focus

1. **A phase completed a second time.** The sync after a slice added to a phase that has its minor version sets a patch version, and its section names that slice alone. Pinned by `release-version-phase.test.js » a slice added to a phase that has its minor version gets a patch version naming that slice alone` (S-51).
2. **A state file removed after red.** Deleting the state file on a slice branch lifts no freeze. Pinned by `check/frozen.test.js » a tip that removed the state file after red is a finding and its frozen tests are still judged` (S-51).
3. **A guard change that lets something through.** S-52 adds denials; the one command it newly follows is a `cd` to a directory the same command creates, and a listed path named after it is still denied. Pinned by `hooks/pre-bash-deny.test.js » a cd to a glob is refused and a cd to a directory the command creates is followed` (S-52).
4. **A deny pattern that stops all work.** A pattern the guards cannot compile is refused when the config is validated, naming its index, in place of a regular-expression error on every tool call. Pinned by `config.test.js » a deny pattern the guards cannot compile is refused, naming its index` (S-52).
5. **A web page that a version makes stale.** The generated page holds no version, so the sync pull request after a merge leaves it equal to what the script writes. Pinned by `guide-page.test.js » the page has a section for every command, slash command and rule page, and no version or date` (S-54).

## Order

**Order:** A; B; C

Groups: A first, then B, then C. S-51, S-52 and S-53 (A) run in parallel because their expected changes share only the shared roots (`docs/runbook.md` and test files): S-51 owns the version code, `build commit`, the `frozen` rule, the journal heads, the workflow generator, the `branch` command and the guide pages of those; S-52 owns the hooks under `src/hooks/` and `src/config.js`; S-53 owns the tracker adapter. Issue #136 and issue #127 both concern the workflow and both sit in S-51; issue #127 changes no code (see S-51, Done when 4). The merge of S-54 leaves every slice of the phase merged, so its sync sets the phase's minor version; each slice of A is a patch version (D-90, D-96).
