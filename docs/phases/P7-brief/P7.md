# Phase 7 — Start from an idea: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan slice by slice, task by task. Steps use checkbox (`- [ ]`) syntax for tracking. Each slice file `S-<nn>-*.md` in this folder is one unit of work with its own tasks; this file holds what every slice shares.

**Goal:** A person who has only an idea can start a program. `/slicekit brief` interviews them one topic at a time and writes `<docsRoot>/brief/<slug>.md` from their answers alone; an answer they cannot give becomes an open question. `/slicekit intake` then takes that brief as its source like any other document (D-99).

**Architecture:** One new CLI command, `slicekit brief`, with the subcommands the slash command runs, in the shape of `slicekit intake`'s interview; one new procedure, `brief`, served by `slicekit instructions --command brief`; one optional stage, `brief`, that `slicekit stage require brief` confirms from files.

- **The interview** (S-56): `slicekit brief start <slug>` names the brief and opens a session in the worktree's own git directory, beside the intake interview's. `brief ask --topic <t> --question <q>` prints `question <n>` and refuses a topic out of the order of REQ-2.15 or a question while the last one has no answer. `brief answer --answer <a>` writes the answer under its section of the brief; `brief answer --unknown` writes the topic under `## Open questions`. `brief done` refuses while a section is missing or a file under `<docsRoot>/spec/` appeared or changed, commits the brief on the spec branch, and prints `/slicekit intake <docsRoot>/brief/<slug>.md`.
- **The stage** (S-56): `brief` is not one of the nine stages of `STAGES`; `stage require brief` judges it alone, and `stage require intake` never reads it (REQ-1.7).
- **The layout** (S-56): `kitPaths` gains `brief`; init lays down `<docsRoot>/brief/` with a `.keep` file, and the layout rule requires the folder (REQ-1.1).
- **The docs** (S-57): the guide index's Stages table, the README's Quick start, a blank brief in the kit for a person who writes one by hand, a brief in `examples/backend`, and the first step of `docs/walkthrough.md`.

**Tech Stack:** As Phases 1 to 6: Node ≥ 22, ES modules, `node:test`, `node:child_process` for git, no dependencies (D-04).

**Spec:** `docs/spec/02-commands-agents-loop.md` (REQ-2.2, REQ-2.15), `docs/spec/01-layout-and-state.md` (REQ-1.1, REQ-1.7), `docs/spec/05-kit-quality-and-release.md` (REQ-5.7, REQ-5.8). Decisions: `docs/decisions.md` (D-99 binds this phase; D-97 and D-98 bind S-57). No slice changes a spec file.

## What already exists

- `STAGES` in `src/stage.js` holds nine stages, from `intake` to `release`; `slicekit stage require <stage>` (`src/cli/stage.js`) refuses a name outside that list with exit 2.
- `slicekit intake` (`src/cli/intake.js`, `src/intake.js`) has the subcommands `snapshot`, `ask`, `answer` and `done`. Its session is `<git-dir>/slicekit/interview.json`, and `kitOwned` in `src/hooks/pre-edit.js` denies an edit to it. `intake done` refuses when a file under the spec directory appeared or changed during the interview.
- `PROCEDURES` in `src/instructions.js` names nine procedures; `slicekit instructions --command <name>` serves `templates/instructions/commands/<name>.md`. Each slash command is a file under `templates/claude-code/commands/` with an entry in `templates/claude-code/manifest.json`.
- `kitPaths` in `src/paths.js` has no brief folder. Init writes each file under `templates/docs/` to the destination `TEMPLATE_DEST` in `src/init.js` names, and throws on a template with none. The layout rule (`src/check/rules/layout.js`) lists the folders it requires in `DIRS`.
- `test/user-guide.test.js` fails when a command of `COMMANDS`, a procedure of `PROCEDURES` or a rule has no page under `docs/guide/`; `test/readme.test.js` fails when the README's "What it covers" table leaves out a template under `templates/claude-code/commands/`; `test/guide-page.test.js` fails when `docs/guide/slicekit-guide.html` differs from what `scripts/guide-html.js` writes.
- `docs/walkthrough.md` starts at `examples/backend`'s first slice, P1/S-01, with the spec and the plan already written.

## Global Constraints

Every constraint of `docs/phases/P1-spine/P1.md`, `docs/phases/P2-loop/P2.md` and `docs/phases/P6-polish/P6.md` holds, except the commit trailer. In addition:

- **The brief holds only the person's words.** No step of `slicekit brief` writes text the person did not give, apart from the seven headings and the topic name of an open question. A test reads the brief after a scripted interview and finds each answer once and nothing else under its heading.
- **The brief writes no spec.** `brief done` refuses when a file under `<docsRoot>/spec/` appeared or changed since `brief start`, as `intake done` does.
- **Intake is unchanged for a person who has a document.** No test of `slicekit intake` or `stage require` that passes before the phase changes.
- **Every git step is in the CLI.** The slash command runs no git or gh command; `brief done` makes the one commit.
- **A new command has its page in the same slice.** The page under `docs/guide/`, the row in the guide index, the README's "What it covers" row and the regenerated web page land with the command, since the tests of the last bullet of "What already exists" fail without them.
- **Subcommand output.** As P2: the first stdout line is the value; findings one per line as `<file>:<line> <message>`; exit 0 success, 1 refused or findings, 2 usage or unknown ID.
- Commits on the kit's own repo end with ONE final block of two lines, `Slice: P7/S-<nn>` immediately followed by the `Co-Authored-By` line of the session that made the commit.

## Review Focus

1. **An invented requirement.** A topic the person cannot answer lands under `## Open questions` and nowhere else. Pinned by `brief.test.js » an unknown answer is written under Open questions and not under its topic` (S-56).
2. **Intake made to wait for a brief.** `stage require intake` on a repository with no file under `<docsRoot>/brief/` gives what it gave before. Pinned by `stage.test.js » stage require intake does not read the brief folder` (S-56).
3. **A brief that writes spec text.** `brief done` with a spec file changed during the interview exits 1 and commits nothing. Pinned by `brief.test.js » brief done refuses when a spec file changed during the interview` (S-56).
4. **A brief template that drifts from the check.** The blank brief's headings are the seven that `stage require brief` requires. Pinned by `brief-docs.test.js » the blank brief holds the seven sections stage require brief checks` (S-57).
